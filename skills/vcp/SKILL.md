# Visual Click Prompt (VCP)

> Visual Click Prompt (VCP) enables developers and designers to click anywhere on a live website, inspect DOM elements, attach in-context prompts, and dispatch structured task briefs directly to local Antigravity AI coding agents.

## Use this skill when

- The user asks to "check visual prompts", "implement FEEDBACK_PROMPT.md", or mentions VCP.
- A task brief exists at `FEEDBACK_PROMPT.md` or in `.gemini/tasks/` generated by the VCP Chrome extension.
- The user asks the agent to "watch for visual prompts" or "monitor live feedback" on a website.
- The user needs to verify, start, or connect with the VCP Bridge daemon (`http://127.0.0.1:8765`).

## Do not use this skill when

- The task is unrelated to in-browser visual feedback, live website annotation, or DOM element inspection.
- The user is working on purely backend, headless database, or low-level systems code with no UI components.

## Instructions

1. **Read Active Brief**: Open and inspect `FEEDBACK_PROMPT.md` (or the latest `.gemini/tasks/task-*.md`) at the project root. Extract target URL, macro instructions, and pin count.
2. **Parse Element Envelopes**: For each numbered pin, extract the user prompt, CSS selector, test ID (`data-testid`), text quote context, and computed styles.
3. **Locate Source Components**: Search the project codebase by test ID, exact text quote, or component classes to identify the exact template, JSX, TSX, Vue, or Svelte file.
4. **Apply Modifications**: Implement the requested visual changes pin-by-pin while preserving overall design hierarchy, responsive guardrails, and accessibility standards.
5. **Verify & Test**: Run project linting, build checks (`npm run build`), and verify mobile viewport guardrails (`min-w-0`, `overflow-x-hidden`).
6. **Provide Walkthrough**: Report changes clearly with before/after explanations for each pin.

### VCP Artifacts in Any Target Workspace

When a user points, clicks, and sends feedback from a live website, the VCP bridge automatically writes structured files into the target project workspace:

- `FEEDBACK_PROMPT.md`: Primary active task brief located at project root containing the latest batch of visual pins and macro instructions.
- `.gemini/tasks/task-<timestamp>.md`: Historical timestamped task brief preserving individual submission batches.
- `.gemini/tasks/feedback-<timestamp>.json`: Machine-readable payload containing exact element geometry, bounding boxes, and DOM trees.
- `agent_inbox.md`: Append-only changelog summarizing all visual feedback events.

### Step-by-Step Execution Protocol

1. **Read `FEEDBACK_PROMPT.md`**:
   - Check the **Target Page URL** and route.
   - Read the **Macro Directive** (overarching design, typography, or styling rules).
   - Count the total pins to verify all are addressed.

2. **Locate Target Files**:
   - Grep for `data-testid` or stable element IDs.
   - Grep for unique rendered text strings.
   - Match routing conventions (e.g. Next.js `app/` routes, Vue `pages/`).

3. **Implement Changes**:
   - Apply edits strictly to the relevant components and CSS styles.
   - Avoid unintentional layout shifts or breaking adjacent components.
   - Ensure RTL/LTR bidirectional support where applicable.

4. **Verify Quality & Responsiveness**:
   - Check that container elements contain `min-w-0` and `overflow-x-hidden`.
   - Run available unit and visual tests.

### Bridge Daemon Diagnostics & Management

If the VCP bridge is not reachable or responding:
- Health check endpoint: `http://127.0.0.1:8765/health`
- Default port: `8765`
- Launch protocol: Windows URL protocol `vcp://start` launches the local bridge daemon directly from the browser.
- Upstream project repository: https://github.com/shatinz/vcp
